【第 2 阶段 · 云端音频播放 验证步骤】

代码已写完并编译通过，等板子到货按下面顺序走。

────────────────────────
准备（在电脑上，一次性）
────────────────────────
1) pip install paho-mqtt
2) 生成 3 秒测试音频（不依赖任何公网资源）：
   python tools/policy_sender.py --make-wav test.wav --seconds 3
3) 在 test.wav 所在目录起个本地服务器：
   python -m http.server 8000
4) 查本机局域网 IP：Windows 用 ipconfig，Mac/Linux 用 ifconfig
   假设是 192.168.1.20，那音频地址就是：
   http://192.168.1.20:8000/test.wav
   ★ 手机热点/同一 WiFi 下才连得上，必须 http:// 不能 https://

────────────────────────
板上（烧录后）
────────────────────────
5) 开机应听到两声「叮咚」= I2S + 功放 + 喇叭 通了
6) 串口打印里抄下 MAC 后缀：
   已订阅策略主题: sa/ir-node-XXXX/policy

────────────────────────
第一步验证：不经过 MQTT，直接用串口试播
────────────────────────
7) 串口里敲：
   u http://192.168.1.20:8000/test.wav
   预期日志：
     连接 192.168.1.20:8000/test.wav (最多等 30 秒)
     已连接，耗时 xxms
     HTTP 200  audio/wav  264644 字节
     WAV 44100Hz 1声道 16bit, 数据 264600
     开始流式播放
     播放结束: 132300 样本 ≈ 3000ms 音频
   ★ 这一段能过，说明"HTTP + WAV 解析 + I2S"整条链路没问题

────────────────────────
第二步验证：走 MQTT 云端策略
────────────────────────
8) 电脑上跑：
   python tools/policy_sender.py --device XXXX
9) 在里面敲：
   url http://192.168.1.20:8000/test.wav
   send
   设备端应打印 [策略] 解析成功 + clip_url 那一行
10) 用手挡一下红外模块
    预期：LED 亮 → 喇叭放 3 秒音频 → 串口打印 播放结束
    播完保持约 0.5 秒后 LED 灭，回待机
11) 设备会上报事件到 sa/ir-node-XXXX/event，
    发送端窗口里会实时显示 play_start / play_done

────────────────────────
出问题怎么定位（日志已经分好层了）
────────────────────────
· 开机没声音          → I2S 初始化失败，看串口有没有 [I2S] 报错
· 连接音频服务器失败  → IP 错 / 电脑防火墙 / 没在同一 WiFi
· HTTP 状态码 404     → 路径不对，检查 http.server 是否在正确目录
· 不是 WAV 文件       → 文件不是 WAV，或下成了 HTML 错误页
· 这是 MP3 流         → 第 2 阶段只支持 WAV，MP3 在第 3 阶段
· chunked 传输不支持  → 换个静态文件服务器（python -m http.server 是可以的）
· 有日志没声音        → 喇叭接线 / 音量 / MAX98357 Vin 供电

────────────────────────
当前版本的能力边界（诚实说明）
────────────────────────
· 只支持 WAV(PCM) 8/16bit 单双声道，不支持 MP3/AAC
· 不支持 chunked 传输
· https 用 setInsecure()，不校验证书（够用但不安全）
· 播放时主循环被 I2S 写阻塞，MQTT 心跳可能延迟，播完自动恢复
