# 后台串口协议 · ESP32 驱赶节点

后台主机（树莓派 / 4G 网关）与节点之间的串口通信协议。
固件侧实现：`src/serial_cmd.cpp`（挂接在 `loop() -> handleSerial()` 里）。

## 总则

- **一行一条 JSON**，以 `\n` 结尾，推荐 115200 波特率（板上标 `USB` 的原生口）
- 设备**每条指令回一行 JSON**，带 `"cmd"` 回显；出问题时回
  `{"status":"error","error":"原因"}`
- 同一个串口上混着人类调试日志（`[WiFi] ...` 之类）。
  **后台解析规则：只处理以 `{` 开头的行**，其余行忽略
- 原有单字符调试命令（`b` `t` `g` `w` `s`…）不受影响，可继续用
- 串口有任何活动，深度睡眠自动推迟 60 秒；后台长时间不发话后，
  设备可能入睡，睡眠中串口命令无效（田野节点平时就是睡着的）

## 7 条指令

### 1. sync_logs —— 回传事件日志

发：
```json
{"cmd":"sync_logs","since":"2025-06-01 12:00:00","limit":200}
```
- `since` 可省（全量回传）。格式 = 日志里 `date` + 空格 + `time`，
  按**字符串比较**过滤（同格式字典序即时间序；只写日期 `"2025-06-01"` 也可以）
- `limit` 默认 200，最大 500；还有剩余时返回 `"more":true`，
  把最后一条的 `date time` 拼成新的 `since` 继续翻页

回：
```json
{"cmd":"sync_logs","status":"ok","count":2,"more":false,"source":"sd","logs":[
  {"date":"2025-06-01","time":"12:30:05","zone":"1号","file":"hawk_scream.wav","result":"start","src":"ntp","uptime_ms":3521},
  {"date":"2025-06-01","time":"12:31:44","zone":"boot","file":"----","result":"boot","src":"est","uptime_ms":112}
]}
```
- `source`：`sd` = 直读卡上 /events.csv；`ram_buffer` = SD 未挂载，
  只能拿到内存里最近 16 条
- `src`：`ntp` = 真实时间可信；`est` = 由 NVS 纪元推算；`none` = 无时间，
  按 `uptime_ms` 排序

### 2. get_status —— 设备状态

发：`{"cmd":"get_status"}`

回：
```json
{"cmd":"get_status","status":"ok","battery_voltage":-1,"battery":"未接入(硬件无分压检测)",
 "temperature":27.4,"humidity":63,"sd_total_mb":30304,"sd_used_mb":142,
 "storage":"TF 卡","sd_mounted":true,"audio_count":6,"uptime_seconds":3521,
 "free_heap_kb":186,"wake_cause":"上电","mqtt_connected":false,
 "wifi_rssi":-58,"ip":"192.168.1.23","time":"2025-06-01 12:30:44"}
```
- `battery_voltage` 现在恒为 -1：硬件没接电池分压检测，接上后固件补 ADC 读数
- `temperature/humidity/time/wifi_rssi` 传感器或网络不在时为 `null`

### 3. upload_audio —— 上传音频（二进制）

**两步**：
1. 发 `{"cmd":"upload_audio","filename":"hawk_scream.wav","size":152644,"crc32":3095520918}`
   - `crc32` 可选但**强烈建议**（后台 `zlib.crc32(data) & 0xffffffff`）
   - 设备回 `{"cmd":"upload_audio","status":"ready","path":"/sd/sounds/hawk_scream.wav"}`
2. 后台**收到 ready 后**才开始灌二进制原始流（不要 base64，不要分包协议）
   - 传输期间暂停发任何其它指令；每 15 秒内必须至少有数据到
   - 结束后设备回最终结果：
     `{"cmd":"upload_audio","status":"ok","filename":"hawk_scream.wav","size":152644,"crc32":3095520918,"audio_count":7}`

失败情况（半截文件已自动删除）：
`{"status":"error","error":"crc_mismatch"}` / `"timeout_waiting_data"` /
`"sd_write_failed"` / `"no_storage"` / `"bad_size"`（上限 8MB）

- 存储位置 = 音频库当前后端：TF 卡挂上时 `/sd/sounds/`，否则板载 Flash `/sounds/`
- 文件名白名单 `[0-9A-Za-z._-]`，路径成分会被剥掉（防穿越），建议 ≤63 字符
- 上传期间设备不响应 PIR 触发；TF 卡 400kHz 慢速挂载时约 30KB/s，1MB 约半分钟
- 上传成功立刻进曲库，下一次触发就能用到

### 6. set_config —— 改配置

两种写法都收：
```json
{"cmd":"set_config","key":"volume","value":"0.8"}
{"cmd":"set_config","config":{"volume":"0.8","trigger_interval":"30","flash_rgb":"255,80,0"}}
```
回：`{"cmd":"set_config","status":"ok","applied":["volume","trigger_interval"],"unknown_keys":[]}`

支持的 key（value 一律字符串）：

| key | 说明 | 例 |
|---|---|---|
| `volume` | 音量 0~1 | `"0.8"` |
| `trigger_interval` | 触发冷却，**秒** | `"30"` |
| `cooldown_ms` | 同上，毫秒（原生字段） | `"30000"` |
| `hold_ms` | 触发后灯保持时长 ms | `"5000"` |
| `tone_hz` / `tone_ms` | 兜底提示音 | `"1200"` / `"250"` |
| `mode` | `trigger` / `mute` | |
| `enabled` | `1`/`0` | |
| `pick` | `random` 随机不重复 / `round` 轮换 | |
| `source` | `local` 本地优先 / `cloud` 云端优先 | |
| `sounds` | 全局曲库，逗号分隔 | `"a.wav,b.wav"` |
| `clip_url` | 云端音频地址 | |
| `flash_enabled` / `flash_rgb` / `flash_count` / `flash_ms` | 爆闪参数 | `"255,80,0"` |

- 结果存 **NVS**，深度睡眠/断电不丢
- ⚠️ 这是**本地兜底配置**：节点连上 MQTT 后，云端策略会把这套配置覆盖
  （优先级：云端 MQTT > 串口 set_config > 固件默认）

### 7. get_config —— 读配置

发：`{"cmd":"get_config"}`

回：`{"cmd":"get_config","status":"ok","config":{"volume":"0.60","enabled":"1",
"mode":"trigger","trigger_interval":"3","cooldown_ms":"3000","hold_ms":"5000",

## 后台侧参考实现（Python 片段）

```python
import zlib, time

def send(dev, obj):
    dev.write((json.dumps(obj, separators=(",", ":")) + "\n").encode())

def read_line(dev, timeout=5):
    dev.timeout = timeout
    line = dev.readline().decode(errors="ignore").strip()
    return json.loads(line) if line.startswith("{") else None

def get_status(dev):
    send(dev, {"cmd": "get_status"})
    return read_line(dev)

def upload_audio(dev, path):
    data = open(path, "rb").read()
    send(dev, {"cmd": "upload_audio", "filename": os.path.basename(path),
               "size": len(data), "crc32": zlib.crc32(data) & 0xffffffff})
    if read_line(dev, 10).get("status") != "ready":
        return False
    for i in range(0, len(data), 4096):        # 流式灌入，别一口气 write
        dev.write(data[i:i+4096])
        time.sleep(0.002)
    return read_line(dev, 30).get("status") == "ok"

def sync_logs(dev, since=None):
    cmd = {"cmd": "sync_logs", "limit": 200}
    if since: cmd["since"] = since
    send(dev, cmd)
    return read_line(dev, 20)
```

## 注意事项

1. 上传时先停播放是固件自动做的（SD 和播放不能并发）
2. 大文件传输依赖 USB 流控：后台 `write` 会被自动减速，不需要自己限速
3. `sync_logs` 的行来源是设备本地 CSV，解析失败的单行会被跳过（不报错）
4. 深度睡眠开启（部署模式）时设备大部分时间在睡，串口指令要在
   它醒着的窗口内发；调试期先用 `z` 关睡眠
